# 《崩坏：星穹铁道》战斗系统"底层逻辑级复刻"可行性研究

> 数据版本：4.6.0（客户端解包数据，2026-09-28）　研究日期：2026-09-29
> 本文回答："能否做出角色·怪物·战斗系统的底层逻辑级完美复刻，用于测试各角色在不同场景下的输出能力？"
> 结论先行：**能做到"数值与公式层面精确一致、机制层面高保真"的复刻；"逐条指令级 100% 完美"理论上可行但成本极高，且有少量内容注定无法仅凭数据确定。** 本仓库的 `hsrsim` 就是按这一路线实现的。

---

## 1. 结论与分层判断

| 层次 | 能否精确复刻 | 依据 | 本项目做法 |
|---|---|---|---|
| **数值**（基础属性、技能倍率、能量、削韧、战技点、星魂/行迹/光锥/遗器参数、击破等级系数表） | ✅ 完全一致 | 直接读取客户端 `ExcelOutput` 表（未经四舍五入，精度高于各类攻略站；例：三月七战技 Lv2 参数 0.40375，攻略站显示 0.4037） | `tools/build_gamedata.py` 自动生成数据快照 |
| **公式结构**（伤害乘区、防御/抗性/易伤/减伤、击破/超击破、DoT、效果命中、行动值） | ✅ 已验证 | 常量在 `GameCoreConstValue`（防御 200+10×等级、易伤上限 350%、减伤上限 99%、暴击不作用于 DoT/击破、伤害无随机浮动等）；结构可从能力脚本中的公式/字段反推 | `hsrsim/formulas.py` + 单元测试 |
| **少数机制常数**（出血 16%/7% 生命上限、风化层数、纠缠 0.6×层数、灼烧/触电倍率、击破debuff 150% 基础概率、RES 90% 上限） | ⚠️ 社区共识 | 这些数值由客户端 C# 代码在运行时注入，**不在数据文件里**；社区（攻略站、fribbels 优化器）已长期对照游戏验证 | 作为常量集中放在 `formulas.py`，可随时校正 |
| **回合/持续时间语义**（何时扣回合、"本回合施加不计本回合"、光环按施放者回合计数、DoT 先结算后恢复韧性） | ✅/⚠️ | 数据中有 `LifeStepMoment`、`LifeStepImmediately` 等字段，规则由这些字段推断，并与游戏内说明文本一致 | `Tick` 枚举 + `skip_first_tick`，每个效果显式声明 |
| **角色/光锥/遗器逻辑** | ✅ 可高保真 | 每个角色的技能逻辑以"可视化脚本"（`Config/ConfigAbility/*.json`）存在，文本描述+参数完全可得 | 每个角色一个 Python 模块，**只写逻辑、所有数字读数据** |
| **敌人 AI、同时触发的内部排序、少量引擎行为** | ❌/⚠️ 无法仅凭数据完全确定 | AI 行为树与部分调度逻辑在客户端代码中；随机数不可复现 | 做成可配置开关（`BattleConfig`），需要用游戏内实测校准 |

### 为什么说"指令级 100% 完美"成本极高

解包数据中的 `ConfigAbility` 是游戏真正执行的技能脚本（修饰器、事件回调、后缀表达式求值），理论上写一个解释器即可"原样执行"。但我们抽样了 13 个角色：

| 角色 | 脚本指令种类 | 指令数 | 文件大小 |
|---|---|---|---|
| 希儿 | 60 | 334 | 100 KB |
| 布洛妮娅 | 57 | 286 | 77 KB |
| 黄泉 | 112 | 1386 | 375 KB |
| 飞霄 | 117 | 1493 | 373 KB |
| 白厄 | 168 | 1575 | 419 KB |

13 个角色合计 **291 种不同指令类型**（其中约一半是镜头/动画/UI 表现），且：
- 哈希化的参数名需逆向（已验证可用 C# 稳定哈希解码）；
- 伤害结算、行动条调度、快照继承黑名单等核心行为在 **C# 客户端代码** 里，脚本只是"调用"它们；
- 每个版本新增指令类型，维护成本随版本线性增长。

因此本项目选择 **"手写逻辑 + 数据驱动数值 + 公式层单独验证"** 的路线：一个角色通常 80–200 行 Python 即可高保真复刻，新版本只需重跑数据脚本并补写新角色。解释器路线作为长期可选方向保留（见 §6）。

## 3. 已确认的核心公式（摘要）

**普通伤害**

```
伤害 = 基础伤害 × (1 + 增伤%) × 防御区 × 抗性区 × 易伤区 × 减伤区 × 韧性区(0.9/1.0)
       × 虚弱区 × 最终伤害区 × 暴击区
基础伤害   = Σ 倍率 × 对应属性（攻击/生命/防御…） + 固定值
防御区     = (L攻+20) / ((L敌+20) × max(0, 1 − 减防 − 无视防御) + L攻+20)    敌人防御 = 200 + 10×等级
抗性区     = 1 − clamp(抗性 − 穿透, −100%, 90%)
易伤区     = 1 + min(Σ易伤, 250%)                  （GameCoreConstValue.DamageTakenRatioMax = 3.5）
减伤区     = Π(1 − 减伤_i)，下限 1%；未击破敌人自带 10% 减伤（即"0.9 韧性区"，与其它减伤相乘）
最终伤害区 = Π(1 + 最终增伤_i)                   （黄泉行迹、遐蝶一魂等"最终伤害"）
暴击区     = 1 + min(暴击率,100%) × 暴击伤害（期望）；DoT 与击破类伤害不能暴击；伤害无随机浮动
```

**击破 / 超击破 / 击破持续伤害**

```
击破伤害   = 等级系数(攻击方等级) × 属性系数 × (0.5 + 最大韧性/40) × (1+击破特攻) × (1+击破增伤)
             × 防御区 × 抗性区 × 易伤区 × 1.0
属性系数   = 物理/火 2，风 1.5，冰/雷 1，量子/虚数 0.5；等级系数 Lv80 = 3767.5535（AvatarBreakDamage 表）
超击破     = 等级系数 × 削韧值/10 × 超击破倍率 × (1+击破特攻) × … ；只统计"命中时目标已处于击破状态"的削韧
击破延后   = 固定 25%（不受击破特攻影响）；量子 +20%×(1+特攻)，虚数 +30%×(1+特攻) 且减速 10%
恢复时机   = 敌人下个回合开始：先结算 DoT/冻结/纠缠（此时仍为击破状态，韧性区 1.0），再恢复韧性，然后正常行动
冻结       = 跳过回合，行动条重置为 50%（等价"解冻后提前 50%"）
```

**行动值 / 能量 / 战技点**

```
行动值 AV = 行动条距离 / 速度，行动条满值 10000；速度变化保留剩余距离
拉条/推条 = 行动条 ∓ X% × 10000
混沌回忆轮次 = 首轮 150 AV，之后每轮 100 AV（"轮次计数器"是速度 100、开局推条 50% 的实体）
能量：普攻 20 / 战技 30 / 终结技 5（逐技能读表），受击多为 10，击杀 10，均乘充能效率（"固定"能量除外）
战技点：初始 3，上限 5
嘲讽值：存护 150，毁灭 125，巡猎/智识 75，其余 100（被击概率 = 嘲讽值 / 总和）
效果命中：概率 = 基础概率 × (1+效果命中) × (1 − 效果抵抗 + 抵抗穿透) × (1 − 特定抵抗)
```

**持续时间**（由 `LifeStepMoment` 等字段推断）

- 默认：持有者**回合结束**时 −1；若在持有者**自己的回合内**获得，则该回合结束不扣（"持续 1 回合"的自身增益覆盖下一回合）。
- 带 `LifeStepImmediately` 的效果（布洛妮娅终结技、停云终结技、瓦尔特禁锢）：当前回合也计数。
- 所有 DoT、击破状态、纠缠/禁锢：持有者**回合开始**结算后 −1。
- 施放者持有的领域/光环（阮•梅、知更鸟、藿藿、缇宝、星期日……）：按**施放者**回合开始计数。

## 5. 无法"完美"或需实测校准的部分

1. **敌人行为**：AI 行为树、技能循环、受击能量（多为 10，部分 5/15/20/25）因怪而异；当前用"按嘲讽值随机选目标的单体攻击"近似，受击回能可配置。对**输出测试**影响主要在"受击回能"和"依赖受击的角色"（如克拉拉、飞霄以外的反击类）。
2. **随机性**：效果命中、弹射目标、敌人选目标都是随机的。暴击默认按期望计算，也可用 `crit_mode: random` + 多种子取平均（`--runs N`）。
3. **同时触发的内部排序**：多个追加攻击/终结技同帧触发时的先后、同行动值时我方与敌方的先后，由客户端调度决定；做成了可调的队列优先级。
4. **快照还是实时**：数据显示 DoT 使用快照实体（`UseSnapshotEntity`），但快照继承黑名单排除了攻击/防御，具体哪些属性被冻结需实测；目前 DoT 使用实时属性。
5. **未在数据中的常数**：见 §1 表格"社区共识"一行。
6. **新版本机制**：每个大版本都会引入新机制（忆灵、欢愉、真实伤害、最终伤害区……），需要跟进实现。
7. **治疗加成的叠加方式**：出/入治疗加成目前按同一乘区相加（与《原神》一致），尚未用本作实测确认是否为相乘。
8. **角色层面的主要近似**（完整清单见代码中的 `# approximation:` / `# not modelled:` 注释）：
   - "离场"类状态（白厄变身期间队友离场、貊泽"离场"）用"移出行动序列 + 不可选中"近似；昔涟对白厄的"颂"按脚本字面实现为变身不结束（可用 `ignition_refreshes` 选项限制），尚未实测。
   - 敌人使用单体普攻 AI，因此依赖"受击""被嘲讽""控制抵抗"的机制（反击、护盾、控制免疫）只做了近似。
   - 我方不会倒下（`allies_immortal`），"受到致命伤害时"类效果以 HP 降到 1 触发。
   - 部分命中拆分在脚本中是动态值或写在循环计数里，这些以命名常量写死在套件中并注明来源。
   - 珀尔（Pearl）的角色配置与技能脚本不在当前解包仓库中，其套件只依据技能文本与参数实现，未能对照脚本审校。
   - 审校中确立的数据约定（能量 `AddValue` 受充能效率影响、`FixedAddValue` 不受；`ModifierPhase1End` 在回合开始阶段计时；护盾在回合结束时计时）已统一应用到全部角色，见 `docs/DEVELOPING.md` §8。

### 建议的校准方法（用游戏内实测把 ⚠️ 变成 ✅）

- 在"模拟宇宙/差分宇宙"或"忘却之庭"选取固定等级敌人，关闭随机（满效果命中、不暴击或全暴击的配装），记录单次伤害数字，与 `hsrsim` 同配置输出逐乘区对比（`Hit.parts` 保存了每个乘区的值）。
- 击破类常数：用无击破特攻、已知最大韧性的敌人测一次击破伤害与 DoT 伤害。
- 持续时间：用速度差明显的队伍观察 buff 图标剩余回合，与 `battle.log_lines` 对照。

## 6. 路线图

1. 引擎细节：敌人行动前事件（`OnBeforeBeingAttacked`）、我方倒下/离场状态、秘技专用行动类型、按单位自身回合计数的冷却、嘲讽目标、能量来源，用于替换各套件中的对应近似。
2. 关卡机制：当期"记忆紊流/增益"与首领特殊阶段、敌人真实技能循环（`MonsterSkillConfig` + AI 配置）、虚构叙事/末日幻影计分。
3. 用游戏内实测校准 §5 中的 ⚠️ 项（尤其是 DoT 快照、同时触发排序、欢愉细节）。
4. 长期可选：`ConfigAbility` 解释器，用于自动交叉核对手写套件（例如比对某次行动产生的修饰器与数值）。
